
### 1. **整体架构**

QEMU 的文档系统使用 **Sphinx** 作为文档生成器，通过 **Meson** 构建系统进行管理，最终由 **Ninja** 执行编译。

**编译流程：**
```
configure → Meson → Ninja → Sphinx → HTML/Man Pages
```

---

### 2. **核心配置文件**

#### 2.1 conf.py - Sphinx 主配置
- **用途**: Sphinx 的核心配置文件
- **关键功能**:
  - 支持两种构建模式：
    - 单独构建各手册 (QEMU 默认方式)
    - 统一构建所有手册 (ReadTheDocs 方式)
  - **必需 Sphinx 版本**: ≥ 3.4.3
  - **主题**: `sphinx_rtd_theme` (Read the Docs 主题)
  - **自定义扩展**（位于 sphinx）:
    - `depfile` - 依赖文件生成
    - `hxtool` - 处理 QEMU 特有的 .hx 文件
    - `kerneldoc` - 从源码注释生成文档
    - `qapi_domain` - QAPI 领域扩展
    - `qapidoc` - QAPI 文档生成
    - `qmp_lexer` - QMP 语法高亮
    - `dbusdoc` - D-Bus 接口文档 (Sphinx ≥ 4.0)

#### 2.2 meson.build - Meson 构建脚本
- **查找 Sphinx**: 在 Python 虚拟环境中查找 `sphinx-build`
- **编译参数**:
  ```bash
  env CONFDIR=/etc/qemu sphinx-build -q \
      -W -Dkerneldoc_werror=1 \  # 警告视为错误
      -j auto \                   # 自动并行化
      -Dversion=<版本> \
      -Drelease=<发行版本>
  ```
- **生成目标**:
  - **HTML 文档**: manual
  - **Man 手册页**: `build/docs/*.{1,7,8}`（根据工具是否启用）

#### 2.3 requirements.txt - Python 依赖
```
sphinx==6.2.1
sphinx_rtd_theme==1.2.2
```

### 3. **编译命令**

#### 3.1 准备工作
```bash
# 1. 配置构建（首次或修改配置后）
mkdir build && cd build
../configure

# 2. 确保 Python 依赖已安装（Meson 会自动创建 pyvenv）
# 构建系统会在 build/pyvenv/ 中自动创建虚拟环境
```

#### 3.2 构建文档
```bash
# 方式 1: 通过 Make（推荐）
make html          # 生成 HTML 文档
make man           # 生成 man 手册页
make sphinxdocs    # 生成所有 Sphinx 文档

# 方式 2: 直接使用 Ninja（从 build 目录）
ninja sphinxdocs
ninja html
ninja man

# 方式 3: 手动调用 Sphinx（调试用）
cd /home/lucas/code/github/qemu_j6
CONFDIR=etc/qemu build/pyvenv/bin/sphinx-build \
    -q -W -j auto \
    -Dversion=10.1.50 \
    -b html \
    -d build/docs/manual.p \
    docs build/docs/manual
```

#### 3.3 输出位置
```bash
build/docs/manual/          # HTML 文档
build/docs/qemu.1           # man 手册页
build/docs/qemu-img.1
build/docs/qemu-nbd.8
# ... 其他手册页
```

### 5. **特殊机制**

#### 5.1 依赖追踪
- 使用 `depfile` 扩展生成 `docs/docs.d`
- 当源文件（.rst、.c 注释等）变化时自动重建

#### 5.2 动态内容生成
- **QAPI 文档**: 从 `qapi/*.json` 自动生成
- **内核文档**: 从 C 源码注释提取（类似 kernel-doc）
- **HX 文件**: 从 `*.hx` 生成命令行选项文档

#### 5.3 版本控制
- 从 VERSION 文件读取版本号
- 自动计算机器类型废弃/删除版本

### 6. **实际构建示例**

```bash
# 完整构建流程
cd /home/lucas/code/github/qemu_j6

# 如果还没配置过
mkdir -p build && cd build
../configure --target-list=arm-softmmu

# 构建 HTML 文档
make html

# 查看生成的文档
ls -lh build/docs/manual/
firefox build/docs/manual/index.html  # 在浏览器打开

# 构建 man 手册页
make man
man build/docs/qemu.1  # 查看手册页

# 安装文档（可选）
make install  # 会将文档安装到 <prefix>/share/doc/qemu/
```

### 7. **调试技巧**

```bash
# 1. 查看详细构建输出
make html V=1

# 2. 单独测试 Sphinx
cd docs
../build/pyvenv/bin/sphinx-build -b html . /tmp/qemu-docs-test

# 3. 检查 Sphinx 版本和扩展
../build/pyvenv/bin/sphinx-build --version
../build/pyvenv/bin/python -c "import sphinx_rtd_theme; print(sphinx_rtd_theme.__version__)"

# 4. 清理文档构建
ninja -C build -t clean
rm -rf build/docs/
```

### 8. **关键发现**

根据分析 build.ninja，实际执行的编译命令为：

```bash
/usr/bin/env CONFDIR=etc/qemu \
    /home/lucas/code/github/qemu_j6/build/pyvenv/bin/sphinx-build \
    -q                          # 静默模式
    -W                          # 警告视为错误
    -Dkerneldoc_werror=1       # kernel-doc 警告也视为错误
    -j auto                     # 自动并行
    -Dversion=10.1.50          # 版本号
    -Drelease=                  # 发行版本（可能为空）
    -Ddepfile=docs/docs.d      # 依赖文件
    -Ddepfile_stamp=docs/docs.stamp  # 时间戳
    -b html                     # 输出 HTML
    -d /home/lucas/code/github/qemu_j6/build/docs/manual.p  # doctree 缓存
    /home/lucas/code/github/qemu_j6/docs                    # 源目录
    /home/lucas/code/github/qemu_j6/build/docs/manual      # 输出目录
```

这个构建系统非常完善，完全集成到 QEMU 的主构建流程中，无需单独管理文档编译。
